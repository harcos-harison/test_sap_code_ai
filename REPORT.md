# REPORT — САП КОД AI-разработчик

1. **Что было сломано:**
   В исходной версии обработчик при повторной доставке создавал новую заявку и уведомление вместо возврата ID уже сохранённой заявки. Также не проверялись корректно обязательные поля: пустой после удаления пробелов `customer` и числовой `external_id` принимались, а пробелы в `source` и `external_id` мешали распознаванию повторов. В исходном логе шести проверок не прошли сценарии повторной доставки, сохранения исходных данных и валидации; также появлялись `ResourceWarning: unclosed database` и `PermissionError: [WinError 32]` при удалении временной базы на Windows.

2. **Что исправлено:**
   - Добавил валидацию события и всех четырёх обязательных полей: `source`, `external_id`, `customer`, `message`.
   - Добавил удаление пробелов по краям полей и отклонение пустых строк и значений неправильного типа.
   - Добавил уникальный индекс по `(source, external_id)`.
   - Реализовал проверку существующей заявки в транзакции `BEGIN IMMEDIATE`: повтор возвращает прежний ID и не создаёт новую заявку или уведомление.
   - Сделал создание заявки и уведомления одной транзакцией с `commit()` и откатом через `rollback()` при исключении.
   - Использовал `contextlib.closing`, чтобы явно закрывать соединение SQLite.
   - Добавил проверки обработки события неправильного типа, обрезки всех полей и чувствительности `source` к регистру.

3. **Как проверено:**
   - Команда: `python -m unittest discover -s tests -v`.
   - Результат после исправлений: **10 тестов пройдены**, `Ran 10 tests in 0.091s`, итог — `OK`.
   - В исходном логе до исправлений указано `Ran 8 tests in 0.208s`; в нём видны провалы сценариев повторной доставки, валидации и нормализации пробелов. Лог не содержит полной итоговой сводки с точным общим количеством ошибок, поэтому я не указываю неподтверждённое число.

4. **AI-инструменты:**
   Использовал Codex для подготовки реализации обработчика и тестов. Использовал ChatGPT для анализа требований задания, разбора исходного лога ошибок и оформления отчёта. Я проверил код и запустил тесты командой, указанной выше.

5. **Git:**
   Для проверки истории использую команду `git log -2 --oneline`. Перед отправкой проверяю актуальный вывод команды и убеждаюсь, что финальные изменения закоммичены.

6. **Оставшиеся ограничения и риски:**
   - Если существующая база уже содержит дубликаты по `(source, external_id)`, создание уникального индекса завершится ошибкой; автоматическая миграция таких данных не реализована.
   - Ошибки SQLite (например, недоступный файл базы) пробрасываются вызывающему коду, а не возвращаются со статусом `invalid`; `invalid` предназначен для некорректных входных данных.
   - `BEGIN IMMEDIATE` сериализует операции записи, поэтому параллельные записи могут ожидать освобождения блокировки.

7. **Фактическое время работы:**
   По моей оценке — около 2 часов, включая анализ исходных ошибок, исправление обработчика, подготовку дополнительных тестов, запуск тестов и оформление отчёта.
